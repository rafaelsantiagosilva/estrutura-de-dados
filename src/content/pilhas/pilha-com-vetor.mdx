Pense em uma pilha de pratos 🍽️. Você coloca um prato novo **em cima** da pilha e, quando precisa de um, também pega o de **cima**. Ninguém tira o prato do meio sem derrubar tudo. Essa regra simples é a base de uma das estruturas de dados mais úteis da computação: a **pilha**. Aqui vamos implementá-la usando **vetores**, com simulações para você ver cada passo acontecendo. 🎬

> 🎮 **Como usar as simulações:** use ▶️ para reproduzir, os botões de passo para avançar ou voltar, e a barra para pular para qualquer momento. A linha destacada no código é a que está executando. A pilha cresce **de baixo para cima**: o índice `[0]` fica embaixo. A seta `top →` mostra a **primeira posição livre**, e células tracejadas estão vazias.

## A regra do jogo: LIFO

Uma pilha é um conjunto de elementos com uma regra:

> 🔑 **O último a entrar é o primeiro a sair.**

Em inglês, *Last In, First Out*, ou simplesmente **LIFO**. Os elementos sempre entram pelo **topo** e sempre saem pelo **topo**.

Compare com outras estruturas:

| Estrutura | Regra | Por onde entra e sai |
| --- | --- | --- |
| **Pilha** | LIFO (último a entrar, primeiro a sair) | só pelo topo |
| **Fila** (como a do supermercado) | FIFO (primeiro a entrar, primeiro a sair) | entra no fim, sai no início |
| **Lista** | sem regra fixa | em qualquer posição |

As duas operações principais têm nomes em inglês que você vai ouvir bastante:

| Operação | Em português | O que faz |
| --- | --- | --- |
| `push` | empilha | insere um elemento no topo |
| `pop` | desempilha | remove o elemento do topo |

E *pilha* em inglês é **stack**.

### Um exemplo no dia a dia do computador: a pilha de chamadas

Todo programa em C usa uma pilha sem você perceber. Imagine que a `main` chama `f1`, e `f1` chama `f2`:

```text
        ┌────────┐
        │   f2   │  ← topo: está executando
        ├────────┤
        │   f1   │  congelada, esperando f2 terminar
        ├────────┤
        │  main  │  congelada, esperando f1 terminar
        └────────┘
```

Quando `f2` termina, ela sai da pilha e `f1` volta a executar. Depois `f1` sai e a `main` continua. Repare: a `main` foi **a primeira** a entrar e é **a última** a sair. Quando ela termina, a pilha de chamadas fica vazia e o programa acaba.

## A ideia: um vetor e uma variável `top`

Para implementar uma pilha com vetor, precisamos de apenas duas coisas:

1. Um **vetor** `v` com capacidade para `MAX` elementos.
2. Uma variável inteira `top`, que começa valendo **zero**.

```text
Pilha vazia (top = 0):

índice:    0     1     2     3     4   ...  MAX-1
         ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
    v    │     │     │     │     │     │ ... │     │
         └─────┴─────┴─────┴─────┴─────┴─────┴─────┘
            ↑
          top = 0


Depois de push(3), push(5), push(7) (top = 3):

índice:    0     1     2     3     4   ...  MAX-1
         ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
    v    │  3  │  5  │  7  │     │     │ ... │     │
         └─────┴─────┴─────┴─────┴─────┴─────┴─────┘
                              ↑
                            top = 3
```

> 💡 **A variável `top` tem dois significados ao mesmo tempo:**
> 1. o **número de elementos** na pilha;
> 2. a **primeira posição livre** do vetor.
>
> Com `top = 3`, há três elementos (nas posições `0`, `1` e `2`) e a posição `3` é a próxima livre. Os dois significados sempre concordam!

## `push`: empilhando

Vamos começar pela versão mais simples, com o vetor e o `top` como **variáveis globais**:

```c
#include <stdio.h>
#define MAX 100

// pilha implementada com vetor (sequencial)
int top = 0;
int v[MAX];

void push(int x)
{
    v[top++] = x;
}
```

Toda a mágica está em uma linha:

```c
v[top++] = x;
```

O elemento `x` é colocado na posição `top` (a primeira posição livre) e, **depois**, `top` é incrementado. É o mesmo que:

```c
v[top] = x;
top = top + 1;
```

Por que o `++` vem depois e não antes? Compare os dois operadores:

| Expressão | O que faz | Qual `top` é usado no índice |
| --- | --- | --- |
| `v[top++]` | usa o `top` e **depois** soma 1 | o valor **antigo** |
| `v[--top]` | subtrai 1 e **depois** usa o `top` | o valor **novo** |

Acompanhe a simulação, que empilha `3`, `5` e `7`. Para caber na tela, usamos `MAX 5`:

Repare em dois detalhes: o `x` aparece nas variáveis quando `push` é chamado, e o marcador `top` só desce **depois** que o valor é escrito.

## `pop`: desempilhando

A função `pop` faz o caminho inverso, também em uma linha:

```c
int pop()
{
    return v[--top];
}
```

Aqui o `--` vem **antes** do `top`. Então primeiro `top` é decrementado e só depois o valor é lido. É o mesmo que:

```c
top = top - 1;
return v[top];
```

Por quê? Porque `top` aponta para a primeira posição **livre**. O elemento do topo está uma posição **abaixo** dela, ou seja, em `top - 1`. Precisamos recuar antes de ler.

Veja a pilha com `3`, `5` e `7` sendo esvaziada:

<Sim name="pilhaVetorPop" />

Juntando tudo, o programa completo da apostila fica assim:

```c
int main()
{
    push(3);
    push(5);
    push(7);
    printf("%d\n", pop());
    printf("%d\n", pop());
    printf("%d\n", pop());
}
```

A saída será:

```text
7
5
3
```

> 🗑️ **Remoção lógica:** quando fazemos `pop`, o valor **não é apagado** do vetor. Ele só deixa de fazer parte da pilha porque está acima do `top`. Isso não é problema: a única forma de chegar naquela posição é com um `push`, que sobrescreve o valor antigo. Foi exatamente o que você viu na simulação: os valores continuaram no vetor, mas fora da pilha.

> 🔄 **Uma utilidade clássica: inverter uma sequência.** Reparou que a saída foi `7 5 3`, o contrário da ordem de entrada? Basta empilhar todos os elementos e depois desempilhá-los. Tente fazer um programa que lê números até aparecer um negativo e imprime tudo na ordem contrária. É a Questão 40 da apostila.

## A pilha só é acessada pelo topo

Uma pilha **só** permite inserir e remover no topo. Se você começar a ler ou alterar posições internas do vetor, ela **deixa de ser uma pilha**. É a restrição que faz a estrutura ser previsível.

A implementação com vetor tem um **ponto fraco**: ela é limitada a `MAX` posições. Se tentarmos empilhar mais que isso, escrevemos fora do vetor. E tem outros problemas na versão global:

- Só existe **uma** pilha no programa inteiro (há só um `v` e um `top`).
- Variáveis globais **não são uma boa prática** de programação.
- `push` e `pop` não verificam se a pilha está cheia ou vazia.

Essa primeira versão serve apenas para **fins didáticos**. Vamos para uma implementação mais adequada.

## Versão melhor: a struct `Pilha`

Em vez de variáveis globais, agrupamos tudo em uma `struct`. Assim podemos ter **várias pilhas**, cada uma com seu vetor e seu `top`:

```c
typedef struct Pilha
{
    int *v;      // o vetor (alocado dinamicamente)
    int max, top; // capacidade e topo
} Pilha;
```

| Campo | Para que serve |
| --- | --- |
| `v` | o vetor que guarda os elementos |
| `max` | a **capacidade** da pilha (quantos elementos cabem) |
| `top` | o topo, com os mesmos dois significados de antes |

### Construtor: `newPilha`

```c
Pilha *newPilha(int max)
{
    Pilha *p = (Pilha *)malloc(sizeof(Pilha));
    p->v = (int *)malloc(sizeof(int) * max);
    p->max = max;
    p->top = 0;
    return p;
}
```

<Sim name="pilhaVetorNew" />

> 🧠 **Cuidado com a notação `p->top`.** Como `p` é um **ponteiro** para a struct, acessamos os campos com `->`. Assim, `p->v`, `p->top` e `p->max` são o vetor, o topo e a capacidade da pilha apontada por `p`.

> ⚠️ O `malloc` **não zera** o conteúdo do vetor. Mas isso não é problema: para ler uma posição, antes é preciso fazer um `push` nela, e o `push` sobrescreve qualquer lixo que estivesse lá.

### `push` com verificação de pilha cheia

Agora o `push` **testa** se ainda existe espaço antes de inserir:

```c
// empilha
void push(Pilha *p, int x)
{
    // verifica se a pilha está cheia
    if (p->top == p->max)
    {
        printf("Erro: Pilha cheia\n");
        exit(1);
    }
    p->v[p->top++] = x;
}
```

A linha `p->v[p->top++] = x;` é a mesma ideia de antes: escreve em `v[top]` e depois incrementa `top`, só que agora via ponteiro. A pilha está cheia quando `top == max`. Nesse momento, não há mais posição livre. Veja o erro acontecendo:

### `pop` com verificação de pilha vazia

O `pop` também ganha seu teste, e aqui separamos o decremento da leitura:

```c
// desempilha
int pop(Pilha *p)
{
    // verifica se a pilha está vazia
    if (p->top == 0)
    {
        printf("Erro: Pilha vazia\n");
        exit(1);
    }
    p->top--;
    return p->v[p->top];
}
```

<Sim name="pilhaVetorVazia" />

> 🛡️ Sem o teste de pilha vazia, o `top--` faria `top` valer `-1`, e `v[-1]` é um acesso **fora do vetor**: comportamento imprevisível. Sempre proteja `push` e `pop`!

### Funções auxiliares

```c
int estaVazia(Pilha *p)
{
    return p->top == 0;
}

// número de elementos na pilha
int size(Pilha *p)
{
    return p->top;
}
```

Aqui o `top` mostra a sua utilidade: como ele é o número de elementos, `size` só precisa devolvê-lo, sem percorrer nada. E `estaVazia` devolve `1` quando `top == 0` e `0` caso contrário (a comparação já produz esse valor).

### Imprimindo a pilha: `printPilha`

Vamos imprimir com o topo do lado **esquerdo**. Para isso, percorremos o vetor de cima para baixo:

```c
void printPilha(Pilha *p)
{
    printf("(");
    for (int i = p->top - 1; i >= 0; i--)
    {
        printf("%d", p->v[i]);
        if (i > 0)
        {
            printf("<-");
        }
    }
    printf(")");
    printf("\n");
}
```

<Sim name="pilhaVetorPrint" />

> 💡 Colocar o topo à esquerda é **opcional**. Poderíamos imprimir com o topo à direita; é só uma escolha de apresentação.

### Juntando tudo

```c
#include <stdio.h>
#include <stdlib.h>

// (struct Pilha, newPilha, push, pop, estaVazia, size e printPilha aqui)

int main()
{
    Pilha *p = newPilha(3);
    push(p, 3);
    push(p, 5);
    push(p, 7);
    printPilha(p);
}
```

A saída será:

```text
(7<-5<-3)
```

> 🧹 **Sobre a memória:** nestes programas não liberamos a memória com `free`. Ela só é devolvida quando o programa termina. O mais correto é fazer um `free` para cada `malloc` usado, e isso fica como exercício (Questão 42).

## Quanto custa cada operação?

Nenhuma operação da pilha com vetor precisa percorrer os elementos para inserir ou remover. Elas só mexem no `top` e em **uma** posição do vetor:

| Operação | Complexidade | Por quê |
| --- | --- | --- |
| `push` | <ComplexityBadge>Θ(1)</ComplexityBadge> | um teste, uma escrita e um incremento |
| `pop` | <ComplexityBadge>Θ(1)</ComplexityBadge> | um teste, um decremento e uma leitura |
| `estaVazia` | <ComplexityBadge>Θ(1)</ComplexityBadge> | uma comparação |
| `size` | <ComplexityBadge>Θ(1)</ComplexityBadge> | só devolve o `top` |
| `newPilha` | <ComplexityBadge>Θ(1)</ComplexityBadge> | não preenche o vetor, só reserva e inicializa campos |
| `printPilha` | <ComplexityBadge>Θ(n)</ComplexityBadge> | percorre os `n` elementos da pilha |

> 🚀 O custo **não depende** de quantos elementos já estão na pilha. Empilhar o milésimo elemento custa o mesmo que empilhar o primeiro.

## Aplicação: parênteses balanceados

Um problema clássico que a pilha resolve com elegância: verificar se os parênteses de uma expressão estão **balanceados**.

| Texto | Resultado | Por quê |
| --- | --- | --- |
| `(2 + 2) + (2 * (2 + 2))` | ✅ balanceado | cada `(` tem seu `)` |
| `2) + (2` | ❌ desbalanceado | o primeiro `)` fecha sem nenhum `(` aberto (note que a quantidade de `(` e `)` é igual!) |
| `(2 * (2 + 2)` | ❌ desbalanceado | um `(` nunca é fechado |

A estratégia usa a regra LIFO: o último parêntese aberto é o primeiro a ser fechado.

1. Toda vez que aparece um `(`, **empilhe**.
2. Toda vez que aparece um `)`, **desempilhe**.
3. Se aparecer um `)` e a pilha estiver **vazia**, a resposta é **desbalanceado**.
4. Se, no final do texto, a pilha **não** estiver vazia, a resposta também é **desbalanceado**.
5. Caso contrário, está **balanceado**.

```c
// devolve 1 se os parênteses estão balanceados
// 0 caso contrário
int balanceado(char *texto)
{
    int size = strlen(texto);
    Pilha *p = newPilha(size);
    for (int i = 0; i < size; i++)
    {
        if (texto[i] == '(')
        {
            push(p, 1);
        }
        if (texto[i] == ')')
        {
            if (estaVazia(p))
            {
                return 0;
            }
            pop(p);
        }
    }
    return estaVazia(p);
}
```

Note que empilhamos sempre o valor `1`: o conteúdo não importa, só queremos **contar** quantos parênteses estão abertos. Veja o caso balanceado:

## Erros comuns

1. **Confundir `v[top++]` com `v[++top]`.** O `push` correto usa `top++` (escreve na posição livre e depois avança). Com `++top`, o primeiro elemento iria para `v[1]` e a posição `0` ficaria desperdiçada.
2. **Confundir `v[--top]` com `v[top--]` no `pop`.** Com `top--`, o programa leria `v[top]` (a posição **livre**, com lixo) e só depois decrementaria. O `pop` correto recua **antes** de ler.
3. **Esquecer os testes.** Sem o teste de pilha cheia, o `push` escreve fora do vetor. Sem o de pilha vazia, o `pop` lê `v[-1]`.
4. **Achar que o `pop` apaga o valor.** Ele só move o `top`. O valor antigo continua no vetor até ser sobrescrito.
5. **Mexer no meio da pilha.** Ler ou alterar posições internas quebra a regra LIFO. Se você precisa disso, talvez precise de uma lista, e não de uma pilha.

## Resumo rápido

- **Pilha** é LIFO: o último a entrar é o primeiro a sair. As operações são `push` (empilha) e `pop` (desempilha), sempre no **topo**.
- Com **vetor**, guardamos os elementos em `v` e usamos a variável `top`, que é ao mesmo tempo o **número de elementos** e a **primeira posição livre**.
- `push`: `v[top++] = x;` (escreve e depois avança).
- `pop`: `return v[--top];` (recua e depois lê).
- O valor "removido" continua no vetor, mas fica acima do `top`.
- O limite da pilha com vetor é a **capacidade** (`max`). Por isso, teste se está **cheia** antes do `push` e se está **vazia** antes do `pop`.
- Na versão com `struct Pilha`, podemos ter várias pilhas, cada uma com `v`, `max` e `top`.
- `push`, `pop`, `estaVazia` e `size` custam <ComplexityBadge>Θ(1)</ComplexityBadge>. Imprimir custa <ComplexityBadge>Θ(n)</ComplexityBadge>.
- Aplicação clássica: verificar **parênteses balanceados** empilhando `(` e desempilhando em cada `)`.
