<Exercicio numero={9} titulo="100n² + 200n² é Θ(n²)">

Mostre que `100n² + 200n²` é `Θ(n²)`.

<Resposta>

#### 💡 A ideia

Lembre do **sanduíche** 🥪: para provar `f(n) = Θ(n²)` precisamos achar três números positivos, `c_1`, `c_2` e `n_0`, tais que, para todo `n ≥ n_0`:

`c_1·n² ≤ f(n) ≤ c_2·n²`

Aqui o enunciado tem uma sutileza: `100n² + 200n²` é simplesmente `300n²`. Então o "sanduíche" fica **colado**: o pão de baixo e o de cima podem ser a mesma coisa.

> ⚠️ **Provável erro de digitação:** a apostila deve querer dizer `100n² + 200n` (o segundo termo seria **linear**, como no exemplo `100n² + 100n + 100` logo acima). Resolvemos as **duas** versões: a do enunciado e a provável.

#### 🧮 Versão do enunciado: 100n² + 200n²

<Derivation
  title="Provando que 100n² + 200n² = Θ(n²)"
  steps={[
    { tex: "f(n) = 100n^2 + 200n^2 = 300n^2", note: "Os dois termos têm o mesmo grau, então somamos os coeficientes." },
    { tex: "300\\,n^2 \\le f(n) \\le 300\\,n^2 \\quad (n \\ge 1)", note: "Escolhemos c_1 = 300, c_2 = 300 e n_0 = 1. Como f(n) é exatamente 300n², vale a igualdade dos dois lados." },
    { tex: "f(n) = \\Theta(n^2)", note: "Existem c_1, c_2 e n_0 positivos que montam o sanduíche. É exatamente a definição." },
  ]}
/>

#### 🧮 Versão provável: 100n² + 200n

<Derivation
  title="Provando que 100n² + 200n = Θ(n²)"
  steps={[
    { tex: "n \\ge 1 \\ \\Rightarrow \\ n \\le n^2", note: "Para n a partir de 1, o n² é pelo menos tão grande quanto n. (Com n = 5: 5 ≤ 25.)" },
    { tex: "100n^2 \\le 100n^2 + 200n", note: "Pão de baixo: o termo 200n é positivo, então jogá-lo fora só diminui a função. Isto dá c_1 = 100." },
    { tex: "100n^2 + 200n \\le 100n^2 + 200n^2 = 300n^2", note: "Pão de cima: trocamos o n por n² (que é maior ou igual). Isto dá c_2 = 300." },
    { tex: "100\\,n^2 \\le f(n) \\le 300\\,n^2 \\quad (n \\ge 1)", note: "Juntando os dois lados, com n_0 = 1." },
    { tex: "f(n) = \\Theta(n^2)", note: "Sanduíche montado." },
  ]}
/>

#### ✅ Resposta

Nas duas versões, <ComplexityBadge>Θ(n²)</ComplexityBadge>. Constantes: `c_1 = 300`, `c_2 = 300`, `n_0 = 1` (enunciado) ou `c_1 = 100`, `c_2 = 300`, `n_0 = 1` (versão provável).

> 🧠 Mesmo sem a prova: um polinômio sempre é `Θ` do seu **termo de maior grau**. A questão 11 prova isso para qualquer polinômio.

</Resposta>

</Exercicio>

<Exercicio numero={10} titulo="n log n é O(n²)">

Mostre que `n log n = O(n²)`.

<Resposta>

#### 💡 A ideia

Para ser `O(n²)`, basta achar `c` e `n_0` tais que `n log n ≤ c·n²` para todo `n ≥ n_0`. Se dividirmos os dois lados por `n`, a pergunta fica mais simples: **o `log n` é menor que `n`?**

Pense em um **elevador** 🛗 contra uma **escada**: o `log n` é o elevador, que sobe devagarinho, e o `n` é a escada, que sobe um degrau por vez. O `log n` **nunca ultrapassa** o `n`. Veja:

| `n` | `n log n` (base 2) | `n²` |
| --- | --- | --- |
| 1 | 0 | 1 |
| 2 | 2 | 4 |
| 8 | 24 | 64 |
| 16 | 64 | 256 |
| 1024 | 10.240 | 1.048.576 |

Ligue as duas curvas e veja que a parábola sempre fica por cima:

<GrowthChart show={["nlog", "n2"]} />

#### 🧮 Prova

<Derivation
  title="Provando que n log n = O(n²)"
  steps={[
    { tex: "n < 2^n \\quad (n \\ge 1)", note: "Cada vez que o n aumenta de 1, o 2^n dobra, enquanto o n só ganha 1. (1 < 2, 2 < 4, 3 < 8, 4 < 16...)" },
    { tex: "\\lg n < \\lg 2^n = n \\quad (n \\ge 1)", note: "Aplicamos o lg (log na base 2) nos dois lados. Como o lg é crescente, a desigualdade se mantém." },
    { tex: "n \\lg n \\le n \\cdot n = n^2 \\quad (n \\ge 1)", note: "Multiplicamos os dois lados por n, que é positivo, e a desigualdade não muda." },
    { tex: "n \\lg n \\le 1 \\cdot n^2 \\quad (n \\ge n_0 = 1)", note: "Escolhemos c = 1 e n_0 = 1." },
    { tex: "n \\log n = O(n^2)", note: "É a definição de O." },
  ]}
/>

#### ✅ Resposta

Provado, com `c = 1` e `n_0 = 1`.

> 💡 **E se o log for na base 10?** Nada muda: `log₁₀ n ≤ lg n` (o log na base 10 é menor), então `n log₁₀ n ≤ n lg n ≤ n²`. Na notação assintótica, a base do log só muda uma **constante**.

> 🧠 **Tem folga!** `n log n` é `O(n²)`, mas **não** é `Θ(n²)`: o `n log n` cresce bem mais devagar que `n²`. Por isso um algoritmo `O(n log n)` (como o MergeSort) é muito melhor que um `O(n²)`.

</Resposta>

</Exercicio>

<Exercicio numero={11} titulo="Todo polinômio de grau k é Θ(x^k)">

Mostre que, dado um polinômio de grau `k`, com o seguinte formato `P(x) = a_0x^0 + a_1x^2 + ... + a_kx^k`, onde os valores `a_i` são constantes, `P(x) = Θ(x^k)`.

<Resposta>

#### 💡 A ideia

> ⚠️ **Provável erro de digitação:** o segundo termo do enunciado é `a_1x^2`, mas deveria ser `a_1x^1`. A prova abaixo serve para o polinômio completo `P(x) = a_0 + a_1x + a_2x² + ... + a_kx^k`. E, como a notação assintótica só vale para funções **positivas**, vamos supor `a_k > 0` (o coeficiente do termo de maior grau) e `k ≥ 1`.

Já provamos casos particulares, como `100n² + 100n + 100 = Θ(n²)`. A ideia é a mesma, mas com letras no lugar dos números. Precisamos do **sanduíche** com `x^k`:

- **Pão de cima:** para `x ≥ 1`, todo `x^i` com `i ≤ k` é no máximo `x^k`. Então trocamos todos por `x^k` e somamos os coeficientes.
- **Pão de baixo:** é a parte delicada, porque os `a_i` podem ser **negativos**. O truque é esperar o `x` ficar grande o bastante para o termo `a_k·x^k` **engolir** todos os outros.

#### 🧮 Prova

<Derivation
  title="Parte 1: o limite superior, P(x) ≤ c_2·x^k"
  steps={[
    { tex: "x^i \\le x^k \\quad (x \\ge 1,\\ 0 \\le i \\le k)", note: "Potência maior dá número maior, desde que a base seja pelo menos 1." },
    { tex: "P(x) \\le |a_0| + |a_1|\\,x + \\cdots + |a_k|\\,x^k \\le \\big(|a_0| + |a_1| + \\cdots + |a_k|\\big)\\,x^k", note: "Primeiro trocamos cada coeficiente pelo valor absoluto (assim os negativos não atrapalham). Depois trocamos cada x^i por x^k." },
    { tex: "c_2 = |a_0| + |a_1| + \\cdots + |a_k|", note: "Esta soma é uma constante positiva. Pronto: P(x) ≤ c_2·x^k para todo x ≥ 1." },
  ]}
/>

<Derivation
  title="Parte 2: o limite inferior, P(x) ≥ c_1·x^k"
  steps={[
    { tex: "B = |a_0| + |a_1| + \\cdots + |a_{k-1}|", note: "B é a soma dos valores absolutos de todos os coeficientes, menos o último." },
    { tex: "P(x) \\ge a_k\\,x^k - B\\,x^{k-1} \\quad (x \\ge 1)", note: "No pior caso, todos os outros termos são negativos. Para x ≥ 1, cada |a_i|·x^i com i < k é no máximo |a_i|·x^(k-1)." },
    { tex: "x \\ge \\frac{2B}{a_k} \\ \\Rightarrow \\ B\\,x^{k-1} \\le \\frac{a_k}{2}\\,x^k", note: "Se x é grande o bastante, o termo negativo é no máximo METADE do termo principal. (Basta multiplicar x ≥ 2B/a_k por x^(k-1) e por a_k/2.)" },
    { tex: "P(x) \\ge a_k\\,x^k - \\frac{a_k}{2}\\,x^k = \\frac{a_k}{2}\\,x^k", note: "Tirar metade do termo principal ainda deixa metade. Isto dá c_1 = a_k / 2." },
  ]}
/>

<Derivation
  title="Juntando as duas partes"
  steps={[
    { tex: "n_0 = \\max\\left(1,\\ \\frac{2B}{a_k}\\right)", note: "O n_0 precisa servir para as duas partes: x ≥ 1 (parte 1) e x ≥ 2B/a_k (parte 2)." },
    { tex: "\\frac{a_k}{2}\\,x^k \\le P(x) \\le c_2\\,x^k \\quad (x \\ge n_0)", note: "O sanduíche está montado, com c_1 = a_k/2 e c_2 = soma de todos os |a_i|." },
    { tex: "P(x) = \\Theta(x^k)", note: "É exatamente a definição de Θ." },
  ]}
/>

#### 🧮 Um exemplo com coeficiente negativo

`P(x) = 3x² − 5x + 7`, ou seja, `k = 2` e `a_k = 3`.

| Constante | Valor | Por quê |
| --- | --- | --- |
| `c_2` | `3 + 5 + 7 = 15` | soma dos valores absolutos |
| `B` | `5 + 7 = 12` | soma sem o último |
| `c_1` | `3 / 2 = 1,5` | metade de `a_k` |
| `n_0` | `max(1, 2·12/3) = 8` | espera o `x` passar de 8 |

Conferindo em `x = 8`: `P(8) = 192 − 40 + 7 = 159`, e `1,5·64 = 96 ≤ 159 ≤ 15·64 = 960`. ✅ (Já em `x = 7` o `n_0` não foi atingido, mas ainda valia: a prova só garante a partir de `n_0`.)

#### ✅ Resposta

`P(x) = Θ(x^k)`, com `c_1 = a_k/2`, `c_2 = |a_0| + ... + |a_k|` e `n_0 = max(1, 2B/a_k)`. Por isso, ao analisar um algoritmo, olhamos **só o termo de maior grau** e jogamos fora o resto.

> 🚀 **Caso fácil:** se **todos** os coeficientes forem positivos, a prova encurta: `a_k·x^k ≤ P(x)` (os outros termos só somam) e `P(x) ≤ (soma dos a_i)·x^k`. Vale com `n_0 = 1`.

</Resposta>

<Exercicio numero={12} titulo="Justifique ou refute">

Justifique ou refute as seguintes afirmativas:

1. Se `f(n) = O(g(n))` então `f(n) = Θ(g(n))`.
2. Se `f(n) = Θ(g(n))` então `f(n) = O(g(n))`.
3. Se `f(n) = Θ(g(n))` então `g(n) = Θ(f(n))`.

<Resposta>

#### 💡 A ideia

Para **refutar** uma afirmação basta **um contra-exemplo**. Para **justificar**, é preciso uma prova que valha para **todas** as funções.

| Afirmativa | Veredito |
| --- | --- |
| 1. `O` implica `Θ` | ❌ **falsa** |
| 2. `Θ` implica `O` | ✅ **verdadeira** |
| 3. `Θ` é simétrico | ✅ **verdadeira** |

Pense assim: `O` é só o **teto** (limite superior), `Θ` é teto **e** piso (o sanduíche inteiro). Ter o teto não garante o piso.

#### 🧮 1. Refutando: O não implica Θ

Contra-exemplo: `f(n) = n` e `g(n) = n²`.

<Derivation
  title="n = O(n²), mas n não é Θ(n²)"
  steps={[
    { tex: "n \\le 1 \\cdot n^2 \\quad (n \\ge 1)", note: "f(n) = O(g(n)) vale, com c = 1 e n_0 = 1." },
    { tex: "f(n) = \\Theta(n^2) \\ \\Rightarrow \\ \\text{existe } c_1 > 0 \\text{ com } c_1\\,n^2 \\le n \\ \\text{para todo } n \\ge n_0", note: "Se fosse Θ, existiria um piso c_1·n² abaixo de n a partir de algum n_0. Vamos ver que isso é impossível." },
    { tex: "c_1\\,n^2 \\le n \\ \\Rightarrow \\ n \\le \\frac{1}{c_1}", note: "Dividimos por c_1·n, que é positivo." },
    { tex: "n > \\frac{1}{c_1} \\ \\text{(e } n \\ge n_0\\text{)} \\ \\Rightarrow \\ \\text{contradição}", note: "Qualquer que seja o c_1 escolhido, basta um n maior que 1/c_1 para a conta quebrar. Logo, não existe c_1." },
  ]}
/>

Em números: com `c_1 = 0,01`, o piso é `0,01·n²`. Em `n = 200`, o piso vale `400`, mas o próprio `n` vale só `200`. O piso **ultrapassou** a função.

#### 🧮 2. Justificando: Θ implica O

<Derivation
  title="Θ implica O"
  steps={[
    { tex: "f(n) = \\Theta(g(n)) \\ \\Rightarrow \\ c_1\\,g(n) \\le f(n) \\le c_2\\,g(n) \\quad (n \\ge n_0)", note: "Hipótese: o sanduíche existe." },
    { tex: "f(n) \\le c_2\\,g(n) \\quad (n \\ge n_0)", note: "Olhando só o pão de cima (o lado direito)." },
    { tex: "f(n) = O(g(n))", note: "É exatamente a definição de O, com c = c_2. (É a ida da questão 14.)" },
  ]}
/>

#### 🧮 3. Justificando: Θ é simétrico

<Derivation
  title="Se f = Θ(g), então g = Θ(f)"
  steps={[
    { tex: "c_1\\,g(n) \\le f(n) \\le c_2\\,g(n) \\quad (n \\ge n_0)", note: "Hipótese: f(n) = Θ(g(n))." },
    { tex: "g(n) \\le \\frac{1}{c_1}\\,f(n)", note: "Da primeira desigualdade, dividimos por c_1 (positivo) e isolamos g." },
    { tex: "\\frac{1}{c_2}\\,f(n) \\le g(n)", note: "Da segunda desigualdade, dividimos por c_2 e isolamos g." },
    { tex: "\\frac{1}{c_2}\\,f(n) \\le g(n) \\le \\frac{1}{c_1}\\,f(n) \\quad (n \\ge n_0)", note: "Juntando: o sanduíche de g, agora feito com f. As novas constantes são 1/c_2 e 1/c_1, também positivas." },
    { tex: "g(n) = \\Theta(f(n))", note: "Mesma definição, com os papéis trocados." },
  ]}
/>

#### ✅ Resposta

1. **Falsa.** Contra-exemplo: `n = O(n²)`, mas `n ≠ Θ(n²)`.
2. **Verdadeira.** `Θ` inclui o limite superior, que é o próprio `O`.
3. **Verdadeira.** Basta inverter as constantes: `1/c_2` e `1/c_1`.

> 🧠 **Resumo:** `Θ` é simétrico (vai e volta), mas `O` **não** é: `n = O(n²)` e, no entanto, `n² ≠ O(n)`. É como "menor ou igual" contra "igual".

</Resposta>

</Exercicio>

<Exercicio numero={13} titulo="Sim ou não? Prove">

Responda "sim" ou "não". Justifique sua resposta com uma prova matemática.

- `10n² + 10n + 100 = O(n²)`?
- `n² = O(10n² + 10n + 100)`?
- `100n³ = O(n⁴)`?
- `n⁴ = O(n³)`?
- `2^n = O(3^n)`?
- `3^n = O(2^n)`?
- `log₁₀(n) = O(log₂ n)`?
- `10n² + 10n + 100 = Θ(n²)`?
- `n² = Θ(10n² + 10n + 100)`?
- `100n³ = Θ(n⁴)`?
- `2^n = Θ(3^n)`?
- `3^n = Θ(2^n)`?
- `log₁₀(n) = Θ(log₂ n)`?

<Resposta>

#### 💡 A ideia

Duas regras resolvem as 13 perguntas:

- **Para dizer SIM:** exiba as constantes (`c`, `n_0`) e mostre que a desigualdade vale.
- **Para dizer NÃO:** mostre que, **qualquer** constante que alguém ofereça, existe um `n` que a derruba (uma **contradição**, como a apostila fez com `n = O(√n)`).

Lembre também: `f = O(g)` quer dizer "`g` é **teto** de `f`", e `f = Θ(g)` quer dizer "`g` é teto **e** piso". Então `Θ` é `O` nos **dois** sentidos (questão 14).

#### ✅ Resposta

| Pergunta | Resposta | Constantes ou motivo |
| --- | --- | --- |
| `10n² + 10n + 100 = O(n²)` | ✅ **Sim** | `c = 120`, `n_0 = 1` |
| `n² = O(10n² + 10n + 100)` | ✅ **Sim** | `c = 1`, `n_0 = 1` |
| `100n³ = O(n⁴)` | ✅ **Sim** | `c = 100`, `n_0 = 1` |
| `n⁴ = O(n³)` | ❌ **Não** | exigiria `n ≤ c`, que falha para `n > c` |
| `2^n = O(3^n)` | ✅ **Sim** | `c = 1`, `n_0 = 1` |
| `3^n = O(2^n)` | ❌ **Não** | exigiria `(3/2)^n ≤ c`, mas `(3/2)^n` cresce sem limite |
| `log₁₀ n = O(log₂ n)` | ✅ **Sim** | `c = 1`, `n_0 = 1` |
| `10n² + 10n + 100 = Θ(n²)` | ✅ **Sim** | `c_1 = 10`, `c_2 = 120`, `n_0 = 1` |
| `n² = Θ(10n² + 10n + 100)` | ✅ **Sim** | `c_1 = 1/120`, `c_2 = 1/10`, `n_0 = 1` |
| `100n³ = Θ(n⁴)` | ❌ **Não** | `O` vale, mas o piso `Ω` falha |
| `2^n = Θ(3^n)` | ❌ **Não** | `O` vale, mas o piso `Ω` falha |
| `3^n = Θ(2^n)` | ❌ **Não** | nem o teto `O` vale |
| `log₁₀ n = Θ(log₂ n)` | ✅ **Sim** | `c_1 = 0,3`, `c_2 = 1`, `n_0 = 1` |

As provas estão abaixo, agrupadas por assunto.

    { tex: "3^n \\ne O(2^n) \\ \\Rightarrow \\ 3^n \\ne \\Theta(2^n)", note: "Θ exige O. Sem o teto, não há sanduíche. Item 12: NÃO." },

#### 🧮 Logaritmos: itens 7 e 13

Na notação assintótica a **base do log não importa**, porque trocar de base só multiplica por uma constante:

<Derivation

  steps={[
    { tex: "\\log_{10} n = \\frac{\\log_2 n}{\\log_2 10}", note: "Fórmula de mudança de base." },
    { tex: "\\log_{10} n = \\frac{1}{\\log_2 10}\\,\\log_2 n \\approx 0{,}301\\,\\log_2 n", note: "log₂ 10 ≈ 3,32, então o fator é cerca de 0,301. É uma constante." },

#### 🏁 O que aprendemos

- **Polinômios** de mesmo grau são `Θ` um do outro (itens 1, 2, 8 e 9).
- **Grau maior** é teto, mas nunca piso: `n³ = O(n⁴)`, mas `n³ ≠ Θ(n⁴)`; e o contrário é falso: `n⁴ ≠ O(n³)`.
- **Bases diferentes** em uma exponencial importam muito: `2^n` e `3^n` estão em classes diferentes.
- **Bases diferentes** em um logaritmo **não** importam: é só uma constante.

> ⚠️ **Cuidado com a armadilha:** `2^n = O(3^n)` é verdade, mas `3^n = O(2^n)` é falso. `O` **não é simétrico**; só `Θ` é (questão 12.3).

</Resposta>

<Exercicio numero={14} titulo="Θ é o mesmo que O e Ω juntos">

Mostre que `g(n) = Θ(g(n))` se e somente se `f(n) = O(g(n))` e `f(n) = Ω(g(n))`.

<Resposta>

#### 💡 A ideia

> ⚠️ **Atenção ao enunciado:** o texto da apostila traz `g(n) = Θ(g(n))` no começo, mas é um erro de digitação. A afirmação correta é `f(n) = Θ(g(n))`, e é essa que vamos provar. (Com `g` dos dois lados a frase seria trivial, porque toda função é Θ dela mesma.)

Pense em um **sanduíche** 🥪: o pão de baixo é o limite inferior (`Ω`) e o pão de cima é o limite superior (`O`). Dizer que `f` é `Θ(g)` é dizer que `f` está **espremida entre dois pães feitos com `g`**: um múltiplo de `g` por baixo e outro por cima.

As três definições, todas para `n` grande o bastante, com constantes positivas:

| Notação | Definição | Em português |
| --- | --- | --- |
| `f(n) = O(g(n))` | existem `c` e `n_0` com `0 ≤ f(n) ≤ c·g(n)` | `g` é um **teto** para `f` |
| `f(n) = Ω(g(n))` | existem `c` e `n_0` com `0 ≤ c·g(n) ≤ f(n)` | `g` é um **piso** para `f` |
| `f(n) = Θ(g(n))` | existem `c_1`, `c_2` e `n_0` com `0 ≤ c_1·g(n) ≤ f(n) ≤ c_2·g(n)` | `g` é teto **e** piso |

Como é um "se e somente se", provamos **os dois sentidos**.

#### 🧮 Ida: Θ implica O e Ω

<Derivation
  title="Se f = Θ(g), então f = O(g) e f = Ω(g)"
  steps={[
    { tex: "0 \\le c_1\\,g(n) \\le f(n) \\le c_2\\,g(n) \\quad (n \\ge n_0)", note: "Hipótese: f(n) = Θ(g(n)). Existem c_1, c_2 e n_0 positivos que fazem isso valer." },
    { tex: "f(n) \\le c_2\\,g(n) \\quad (n \\ge n_0)", note: "Olhando só o lado direito do sanduíche: é exatamente a definição de O, com c = c_2." },
    { tex: "0 \\le c_1\\,g(n) \\le f(n) \\quad (n \\ge n_0)", note: "Olhando só o lado esquerdo: é exatamente a definição de Ω, com c = c_1." },
    { tex: "f(n) = O(g(n)) \\ \\text{ e } \\ f(n) = \\Omega(g(n))", note: "Os dois lados do sanduíche já estavam na hipótese. Basta separá-los." },
  ]}
/>

#### 🧮 Volta: O e Ω juntos implicam Θ

<Derivation
  title="Se f = O(g) e f = Ω(g), então f = Θ(g)"
  steps={[
    { tex: "f(n) = O(g(n)) \\Rightarrow 0 \\le f(n) \\le c_2\\,g(n) \\quad (n \\ge n_a)", note: "A definição de O nos dá uma constante c_2 e um ponto de partida n_a." },
    { tex: "f(n) = \\Omega(g(n)) \\Rightarrow 0 \\le c_1\\,g(n) \\le f(n) \\quad (n \\ge n_b)", note: "A definição de Ω nos dá outra constante c_1 e outro ponto de partida n_b." },
    { tex: "n_0 = \\max(n_a,\\, n_b)", note: "Os pontos de partida podem ser diferentes. Escolhendo o maior, a partir de n_0 as duas desigualdades valem ao mesmo tempo." },
    { tex: "0 \\le c_1\\,g(n) \\le f(n) \\le c_2\\,g(n) \\quad (n \\ge n_0)", note: "Juntando as duas: o sanduíche está montado." },
    { tex: "f(n) = \\Theta(g(n))", note: "É exatamente a definição de Θ." },
  ]}
/>

#### ✅ Resposta

Provamos os **dois sentidos**: `Θ` quer dizer "teto e piso ao mesmo tempo". Por isso, quando você acha o `O` e o `Ω` de um algoritmo com a **mesma** função `g`, pode afirmar `Θ(g)`.

> 🧠 **Exemplo:** `3n² + 4n + 2` é `O(n²)` e também `Ω(n²)`, logo é `Θ(n²)`. Já `n²` é `Ω(n)`, mas **não** é `O(n)`: por isso `n²` não é `Θ(n)`.

</Resposta>

Só que o `c` depende da **sua máquina** (processador, compilador...). Pense em um **táxi** 🚕: a fórmula do preço é `preço = valor_por_km × km`. O formato da conta é igual para todos os táxis, mas o `valor_por_km` muda de cidade para cidade. Aqui o `c` é o "valor por km" do seu computador.

O plano tem dois passos:

1. **Calibrar:** medir **uma vez** um `n` grande e descobrir o `c`.
2. **Prever:** usar esse `c` para estimar qualquer outro `n`, sem esperar o programa rodar.

> ⚠️ **Erro clássico: a regra de três.** Se o programa gastou 1 s para `n`, quanto gasta para `10n`? A regra de três diz 10 s, mas isso só vale para funções **retas** (lineares). Como aqui `T` é uma **parábola**, multiplicar `n` por 10 multiplica o tempo por **100**: `T(10n) = c·(10n)² = 100·c·n² = 100·T(n)`.

O programa medido é o da apostila (seleção do maior). Repare que o tempo é medido **só em volta da `ordena`**, e não da geração do vetor:

```c
// posição do maior elemento: Θ(n)
int maximo(int v[], int n)
{
    int max = 0;

    for (int i = 1; i < n; i++)
    {
        if (v[i] > v[max])
        {
            max = i;
        }
    }

    return max;
}

// ordenação por seleção: Θ(n²)
void ordena(int v[], int n)
{
    while (n > 1)
    {
        int max = maximo(v, n);   // acha o maior do trecho atual

        int aux = v[n - 1];       // troca o maior com a última posição
        v[n - 1] = v[max];
        v[max] = aux;

        n--;                      // o último já está no lugar: ignora ele
    }
}
```

#### 🧮 f7: duas chamadas recursivas

Sem laço, a conta vem de uma **recorrência**. Cada chamada com `n > 0` faz **duas** chamadas com `n - 1`, mais um trabalho constante `c`. No caso base (`n = 0`) o custo é uma constante:

<Derivation
  title="Resolvendo a recorrência de f7"
  steps={[
    { tex: "T(n) = 2\\,T(n-1) + c", note: "Duas chamadas de tamanho n-1 e o trabalho constante da soma." },
    { tex: "T(n) = 2\\,\\big( 2\\,T(n-2) + c \\big) + c = 4\\,T(n-2) + 3c", note: "Expandindo uma vez: substituímos T(n-1) pela própria fórmula." },
    { tex: "T(n) = 8\\,T(n-3) + 7c", note: "Expandindo de novo. Repare no padrão: os coeficientes são 2, 4, 8 e as constantes são 1, 3, 7." },
    { tex: "T(n) = 2^k\\,T(n-k) + (2^k - 1)\\,c", note: "Depois de k expansões." },
    { tex: "T(n) = 2^n\\,T(0) + (2^n - 1)\\,c", note: "Expandimos até k = n, quando chegamos ao caso base T(0)." },
    { tex: "T(n) = \\Theta(2^n)", note: "O termo 2^n domina." },
  ]}
/>

Outro jeito de enxergar: o número de chamadas **dobra a cada nível** (1, 2, 4, 8...), e são `n + 1` níveis. O total é `1 + 2 + 4 + ... + 2^n = 2^(n+1) - 1` chamadas. E a própria `f7(n)` devolve `2^n`, a mesma conta do número de folhas. 🌳

<Exercicio numero={17} titulo="Uma função Θ(2^n)">

Proponha uma função com complexidade `Θ(2^n)`: (a) usando `for`/`while`; (b) sem usar `for`/`while`.

<Resposta>

#### 💡 A ideia

Uma função `Θ(2^n)` precisa fazer cerca de `2^n` operações: o dobro a cada vez que o `n` sobe **uma** unidade. Há dois jeitos clássicos:

- **(a) Com laço:** um `for` que dá exatamente `2^n` voltas. Em C, o jeito rápido de calcular `2^n` é o deslocamento de bits `1LL << n` (o `LL` é para o número caber em 64 bits).
- **(b) Sem laço:** recursão com **duas chamadas** de tamanho `n-1`, como a `f7` da questão anterior. A cada nível o número de chamadas dobra.

#### 💻 Código

```c
// (a) com for: dá 2^n voltas
long long expFor(int n)
{
    long long aux = 0;
    long long total = 1LL << n; // 2^n calculado uma única vez

    for (long long i = 0; i < total; i++)
    {
        aux++;
    }

    return aux; // devolve 2^n
}

// (b) sem for/while: duas chamadas recursivas
long long expRec(int n)
{
    if (n == 0)
    {
        return 1;
    }

    long long x = expRec(n - 1);
    long long y = expRec(n - 1);

    return x + y; // devolve 2^n
}
```

> ⚠️ Em `expFor`, calcule o `total` **fora** do laço. Se você escrevesse `i < (1LL << n)` no teste, o cálculo se repetiria a cada volta (o mesmo erro do `media` dentro do `dvp` da apostila). Aqui seria só uma constante a mais por volta, mas é um mau hábito. Use `n` até uns 62, para o resultado caber em `long long`.

#### 🧮 Complexidade

<Derivation
  title="Contando o custo das duas versões"
  steps={[
    { tex: "T_a(n) = c \\cdot 2^n + d", note: "Versão (a): o laço dá 2^n voltas, cada uma de custo constante c, mais um resto d." },
    { tex: "T_b(n) = 2\\,T_b(n-1) + c", note: "Versão (b): a mesma recorrência da f7 da questão 16." },
    { tex: "T_b(n) = 2^n\\,T_b(0) + (2^n - 1)\\,c", note: "Resolvida expandindo n vezes, como na questão 16." },
    { tex: "T_a(n) = T_b(n) = \\Theta(2^n)", note: "As duas crescem exatamente como 2^n." },
  ]}
/>

Veja o quanto a curva exponencial **foge** das outras. Ligue `n`, `n²` e `2ⁿ` e arraste o `n máx`:

<GrowthChart show={["n", "n2", "2n"]} />

> 🚨 **Por que algoritmos exponenciais são "os piores"?** Suponha `10⁻⁶ s` por operação. Para `n = 40`, `2^40` operações levam cerca de `12,7 dias`. Para `n = 60`, mais de `36 mil anos`. Eles só são viáveis para `n` muito pequeno.

#### ✅ Resposta

<ComplexityBadge>Θ(2^n)</ComplexityBadge> nas duas versões: **(a)** `expFor`, com um `for` de `2^n` voltas; **(b)** `expRec`, com duas chamadas recursivas de `n-1` (igual à `f7`).

<Exercicio numero={18} titulo="Descobrindo a constante de T(n) = n³·cte">

Suponha que `T(n) = n³·cte` s. Se `T(10.000) = 1000 s`, qual a constante de tempo? Qual o tempo `T(10⁶)`?

<Resposta>

#### 💡 A ideia

É o mesmo método da questão 15, só que com um **cubo** no lugar do quadrado:

1. **Calibrar:** usar o par `(n, T(n))` que o enunciado dá para descobrir a constante.
2. **Prever:** usar a constante para calcular o tempo de outro `n`.

#### 🧮 Complexidade

<Derivation
  title="Passo 1: a constante de tempo"
  steps={[
    { tex: "T(10^4) = (10^4)^3 \\cdot cte = 1000 \\ \\text{s}", note: "Substituímos n = 10.000 = 10^4 no modelo." },
    { tex: "10^{12} \\cdot cte = 10^3 \\ \\text{s}", note: "(10^4)^3 = 10^12 e 1000 = 10^3." },
    { tex: "cte = \\frac{10^3}{10^{12}} = 10^{-9} \\ \\text{s}", note: "Isolamos a constante. É o tempo de uma 'operação' desta máquina: 1 nanossegundo." },
  ]}
/>

<Derivation
  title="Passo 2: o tempo para n = 10^6"
  steps={[
    { tex: "T(10^6) = (10^6)^3 \\cdot 10^{-9} \\ \\text{s}", note: "Trocamos n por 10^6, já com a constante que achamos." },
    { tex: "T(10^6) = 10^{18} \\cdot 10^{-9} \\ \\text{s} = 10^{9} \\ \\text{s}", note: "10^18 vezes 10^(-9) dá 10^9." },
    { tex: "T(10^6) = \\frac{10^9}{31\\,536\\,000} \\ \\text{anos} \\approx 31{,}7 \\ \\text{anos}", note: "Um ano tem 365 × 24 × 3600 = 31.536.000 segundos." },
  ]}
/>

> 🧠 **Conferindo sem a constante:** de `n = 10⁴` para `n = 10⁶` o `n` foi multiplicado por **100**. Em um algoritmo cúbico, o tempo é multiplicado por `100³ = 10⁶`. Então `T(10⁶) = 10⁶ · 1000 s = 10⁹ s`, o mesmo resultado. 👍

#### ✅ Resposta

- **Constante:** `cte = 10⁻⁹ s`.
- **Tempo:** `T(10⁶) = 10⁹ s`, ou seja, cerca de **31,7 anos**. Um algoritmo `Θ(n³)` é inviável para `n` de um milhão.

</Resposta>

<Exercicio numero={19} titulo="Como a constante c(n) se comporta">

Considere o programa de ordenação descrito a partir da página 29. Calcule a constante de tempo `c` para a função `ordena`, executando o programa em seu computador. Atenção: não utilize compiladores online, como o OnlineGDB, pois eles podem interferir na determinação da constante de tempo.

A constante deve ser calculada a partir da fórmula `c = T(n) / n²`, onde `T(n)` representa o tempo de execução medido para ordenar um vetor de tamanho `n`.

1. Para cada valor de `n` no conjunto `{1, 5, 10, 20, 100, 200, 500, 1000, 10000, 100000, 1000000}`, meça o tempo `T(n)` e calcule a constante correspondente `c(n)`.
2. Analise e descreva o comportamento da constante `c(n)` à medida que `n` aumenta. Discuta se os valores de `c(n)` se estabilizam ou variam de forma significativa conforme o tamanho do vetor cresce.

<Resposta>

#### 💡 A ideia

Na questão 15 supusemos que `T(n) = c·n²` **exatamente**. Mas o tempo real tem também termos menores. Pense na **corrida de táxi** 🚕: o preço tem uma **bandeirada** fixa mais o valor por km.

- Numa corrida **curta** (poucos km), a bandeirada pesa muito. O "preço por km" (preço total ÷ km) fica **alto e bagunçado**.
- Numa corrida **longa**, a bandeirada quase não faz diferença, e o preço por km **se estabiliza** no valor da tabela.

A constante `c(n) = T(n)/n²` é o "preço por km": para `n` pequeno, os termos pequenos (a "bandeirada") dominam. Para `n` grande, eles somem.

#### 🧮 Por que `c(n)` se estabiliza

O tempo real da `ordena` não é só `n²`. Na apostila contamos `n²/2 + n/2 - 1` operações do `maximo`, e as demais operações são `Θ(n)`. Então o tempo tem a forma geral `A·n² + B·n + D`, com `A`, `B` e `D` constantes da máquina:

<Derivation
  title="Quem manda em c(n) quando n cresce"
  steps={[
    { tex: "T(n) = A\\,n^2 + B\\,n + D", note: "Um termo quadrático, um linear e uma constante (a 'bandeirada')." },
    { tex: "c(n) = \\frac{T(n)}{n^2} = A + \\frac{B}{n} + \\frac{D}{n^2}", note: "Dividimos tudo por n²." },
    { tex: "\\lim_{n \\to \\infty} c(n) = A", note: "Os termos B/n e D/n² tendem a zero quando n cresce. Sobra só A." },
    { tex: "c(n) \\to A \\ \\text{(a constante do termo dominante)}", note: "Por isso a constante 'estabiliza': para n grande, c(n) é praticamente o A." },
  ]}
/>

#### 🧮 O que esperar da tabela

Com os dados reais da apostila:

| `n` | `T(n)` | `c(n) = T(n) / n²` |
| --- | --- | --- |
| 10 | 0,003 ms | `3·10⁻⁵ ms` (quase **28 vezes** maior!) |
| 100.000 | 10.723 ms | `1,0723·10⁻⁶ ms` |
| 200.000 | 42.734 ms | `1,0684·10⁻⁶ ms` |

Repare: entre `n = 100.000` e `n = 200.000` o `c(n)` quase não mudou (diferença de cerca de 0,4 %). Já em `n = 10` ele está muito longe. Para o conjunto pedido, o comportamento esperado é:

| Faixa de `n` | O que acontece com `T(n)` e `c(n)` |
| --- | --- |
| `1`, `5`, `10`, `20` | `T(n)` é tão pequeno que o relógio mal consegue medir (pode dar `0`). O `c(n)` é **ruído**: não confie nele. |
| `100` a `1.000` | O tempo ainda é muito pequeno. O `c(n)` **oscila** e tende a ficar **acima** do valor final. |
| `10.000` a `1.000.000` | Os termos menores já são desprezíveis. O `c(n)` **se estabiliza**, perto de `10⁻⁶ ms` (o valor exato depende da sua máquina). |

> 🧠 **Para `n` pequeno, o `T(n)` é "quase zero" e o relógio não tem resolução para medi-lo.** Um truque é rodar a `ordena` **muitas vezes** (gerando um vetor novo a cada vez) e dividir o tempo total pelo número de repetições. Para `n` bem grande (um milhão), o vetor de `4 MB` pode não caber no cache do processador, e o `c(n)` pode subir um pouco: é um efeito do hardware, e não da análise de complexidade.

#### ✅ Resposta

- **`c(n)` não é constante para `n` pequeno:** ele é alto e instável, porque a bandeirada (`D/n²`) e o termo linear (`B/n`) pesam mais, e porque o tempo é pequeno demais para medir bem.
- **`c(n)` se estabiliza para `n` grande:** converge para `A`, a constante do termo dominante. Em `n = 100.000` e `n = 200.000`, ele varia menos de 1 %.
- **Lição:** é por isso que se calibra a constante com um `n` **grande**, como fizemos na questão 15, e que a notação assintótica só se importa com o comportamento quando `n` cresce.

</Resposta>
